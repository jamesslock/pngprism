# Provenance

Where this code came from, what it was and was not derived from, and what
ships inside it. Engineering record, not legal advice.

## What pngprism is a port of

pngprism is a seam-by-seam Rust port of a Python reference implementation —
the deterministic quantize → dither → pack pipeline written for the
compression research program this crate came out of. The port introduced no
new algorithms; each stage was gated on producing byte-identical output to the
reference.

That reference is not a historical artifact. It is **vendored into this
repository** at [`tests/oracle/`](tests/oracle/) and run as a subprocess by the
test suite, which compares the two implementations on every CI run. A port
whose oracle is left behind stops being a port and becomes a fork; keeping it
here is what prevents that. The four vendored modules are digest-pinned by
`tests/oracle_pins.rs`, so an edit to the copy fails the suite.

## What it was not derived from

**No pngquant or libimagequant source was consulted.** They appear in this
program only as black-box measurement baselines — invoked as subprocesses to
produce comparison outputs, never linked, imported, called through an API, or
translated. libimagequant is GPL; this crate is MIT OR Apache-2.0, and that
separation is deliberate and was reviewed rather than assumed.

The reference implementation itself was written from published algorithms and
permissively licensed sources; see [`REFERENCES.md`](REFERENCES.md) for the
derivation ledger.

## Vendored zlib

The DEFLATE backend is **statically vendored stock zlib 1.3.1**, so IDAT output
matches Python's `zlib.compress(data, 9)` byte for byte — a hard requirement
for the cross-implementation determinism guarantee.

- Via `libz-sys =1.1.20` with features `libc, static, stock-zlib`, which
  compiles its bundled stock zlib and bypasses host discovery. `flate2 =1.1.9`
  is routed onto that same C backend; the pure-Rust `miniz_oxide` backend is
  deliberately excluded, because it would not reproduce the same bytes.
- zlib 1.3.1, tarball sha256
  `9a93b2b7dfdac77ceba5a558a580e74667dd6fede4585b91eefb60f03b72df23`, from
  `https://zlib.net/fossils/zlib-1.3.1.tar.gz`.
- CVE posture: [`docs/security-zlib-cve-posture.md`](docs/security-zlib-cve-posture.md)
  — no known zlib CVE is reachable through this crate's call surface.

zlib is distributed under the zlib license; its text is in
[`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md).

## Test fixtures and their licenses

Everything here is either the project's own work or carries an explicit
redistribution grant — checked file by file, not assumed:

| Fixture | Origin | Terms |
|---|---|---|
| `tests/pngsuite/` | Willem van Schaik's PngSuite conformance corpus | explicit grant to use, copy, modify and distribute; upstream `LICENSE` and `README` ship alongside |
| `tests/smoke/` | 12 generated by the project, 12 from Kenney asset packs | CC0-1.0 both; see [`tests/smoke/README.md`](tests/smoke/README.md) |
| `tests/edge/`, `tests/adversarial/`, `tests/never_worse/`, `tests/amplification/` | the project's own committed generators | project's own work |
| `fuzz/corpus/` | deterministically derived from the two corpora above | project's own work |
| `tests/oracle/`, `tests/tools/` | the project's own Python | MIT OR Apache-2.0 |

Fixtures whose licenses could not be established are **not** in this
repository, and neither is the project's own benchmark image, which is
CC BY-SA 3.0 — share-alike obligations do not belong in a permissively licensed
crate. That is why two test corpora are smaller here than in development, a
difference the suite asserts rather than hides.

## Repository history

This repository begins with a single initial commit. The crate was developed
inside a research monorepo across roughly 3,000 commits, and that history is
preserved privately rather than discarded — it was not published because those
commits carry third-party corpora that cannot be redistributed, and a public
object store is permanent.

The practical consequence for a reader: claims in these documents that cite
internal experiments or measurement records refer to material you cannot open.
Those claims are reported with their methodology and their failure cases so
they can be judged on their face — and everything the code itself asserts,
determinism and losslessness and the CLI contract and agreement with the
reference implementation, you can run here and check.
